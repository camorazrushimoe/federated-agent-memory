# H2v3 — Fitness for Purpose

Новый изолированный эксперимент. Не патч H2v2 и не возврат ранкера.

H2v2 закрыл поиск: закрытый словарь процедур + S3 по `problem_shape`
дают ось (D4 **FIT**, recall 0.81, медиана кандидатов 10). Ранкер внутри
ячейки на срезе 60 ничего не добавил (T.hit = B1.hit = 38). См.
[`../h2v2-categorical-scoped-memory/REPORT.md`](../h2v2-categorical-scoped-memory/REPORT.md).

Оставшийся продуктовый вопрос **не про hit по `gold_useful`**. Золото
агентное и почти коллинеарно той же FAQ-ячейке: «попали в useful-список»
не доказывает, что целая прошлая сессия *помогает ответить на этот
запрос*. Этот стенд меряет именно это.

## Гипотеза

Подмешать **одну** прошлую целую сессию из той же процедуры (живой S2 +
S3 exact `problem_shape`, без рейтинга) помогает сильному ризонеру решить
текущий запрос лучше, чем:

- тишина (B0),
- случайная прошлая сессия без фильтра тегов (B_raw),

и не хуже осмысленного потолка агентного золота (B_gold) настолько, что
разрыв объясняется дырой поиска, а не бесполезностью пакета.

Единица анализа — один query из замороженного среза 60.
Исход — судейское **helps / neutral / hurts** в слепом парном сравнении,
не пересечение id с `gold_useful`.

## Вердикт раунда 0

Ещё не измерен. После прогона судьи одна строка: **FIT** /
**FIT WITH LIMITS** / **NOT FIT**. Критерии зафиксированы в
[`EVAL-PLAN.md`](./EVAL-PLAN.md) §6 **до** живого судьи.
