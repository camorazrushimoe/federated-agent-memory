# H2 — бриф для лабы

Документ передачи. Читать в таком порядке: [`README.md`](./README.md) → [`SPEC.md`](./SPEC.md) → [`PROMPTS.md`](./PROMPTS.md) → [`EVAL-PLAN.md`](./EVAL-PLAN.md) → [`CHECKS.md`](./CHECKS.md) → [`RUN-PROTOCOL.md`](./RUN-PROTOCOL.md).

**Заказ:** собрать runnable-контур «целая сессия как подсказка», измерить его и ответить одной строкой: **FIT / FIT WITH LIMITS / NOT FIT**.

**Чего нет в заказе:** новая идея, свой датасет «потому что этот некрасивый», эмбеддинги, сервис, база, импорт H1-кода, сравнение hit с карточками H1.

## 5. Как гонять

Одна команда, одна папка, один манифест — [`RUN-PROTOCOL.md`](./RUN-PROTOCOL.md).

Стадии EVAL-PLAN §9: S0 smoke → S1 dev → S2 full → (S3) → S4 verdict.
Hold-out / золотые useful-пары замораживать до S2. Дописывать пары после увиденного `hit` нельзя.

Пока нет runner, инженер гоняет шаги по одному:

```
python bin/ingest.py   --in fixtures/dialogues.jsonl
python bin/tag.py      --in data/dialogues.jsonl
python bin/retrieve.py --query fixtures/queries/d-007.json --pool data/sessions.jsonl
python bin/rank.py     --candidates data/candidates.jsonl --ratings data/ratings.jsonl --tag-key ...
python bin/mix.py      --ranked data/ranked.jsonl --pool data/sessions.jsonl
python bin/outcome.py  --query ... --packet data/packet.json --source gold --gold fixtures/gold_useful.jsonl
python bin/update.py   --outcome data/outcomes.jsonl --ratings data/ratings.jsonl
```

Когда runner есть — только он. Свою логику в `replay.py` не класть.

## 6. Что нельзя перепутать

Четыре числа, четыре разных отказа:

1. Плохие теги → чинить S2 / промпт (промпт заморожен: чинить только после нового run id).
2. Теги живые, поиск пустой на золотой паре → S3 или `TAG_FIELDS_MIN`, не ранкер.
3. Поиск живой, в пакете одни и те же id → ротация, смотреть `top3_share` и B2.
4. `hit` выше B1, пакет огромный → это не провал идеи, это цена. Вердикт `FIT WITH LIMITS`, рычаг — нарезка. Нарезку в этом проходе не делать.

L1 не тащить в отчёт как «система работает».
T без B1 не тащить как результат.

## 7. Стоп и эскалация

Остановиться и написать заказчику, если:

- аудит A1–A6 показывает, что порог §6.2 недостижим;
- HARD не проходит без правки SPEC;
- провайдер не отвечает так, что прогон нельзя повторить;
- хочется завести второй `bin/` или поменять промпт «чтобы цифра выросла»;
- хочется открыть L3 или вторую модель без отдельного решения.

Порог после увиденного числа не двигаем. Только до прогона, только в EVAL-PLAN, только с арифметикой.

## 8. Формат отчёта за раунд

Без воды.

```
ROUND n · FROM: <роль>
DELIVERABLE: D<k> — <одна строка>
ARTIFACT: <sha / run_id>
NUMBERS: <только измеренные, с n>
CHECKS: <hard passed>/<hard total>, soft: <n>
BLOCKED: <что, или nothing>
NEXT: <одно следующее действие>
```

Вердикт в конце D7 — ровно одна строка §6.4, не абзац.
