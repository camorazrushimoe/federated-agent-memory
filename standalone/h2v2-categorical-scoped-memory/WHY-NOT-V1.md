# Почему H2 v1 закрыт и зачем отдельная папка

Источник: PR #63 (R3), PR #64 (R4), комментарий-handoff на #64.

## Честный результат v1

На срезе n=60 подмешивание целой сессии через обучаемый ранкер **не бьёт**
случайную похожую сессию. Вердикт: **NOT FIT**.

Пайплайн от A до Я живой. Сломан не ранкер, а язык тегов.

## Замер, не догадка

- `channel=web`, `vertical=customer-support` — константы по пулу
- `constraint=none` у 81%, `ending=resolved` у 93% — почти константы
- `problem_shape` — свободный текст, почти уникален: 7 точных совпадений
  между 60 запросами и 320 сессиями пула

Точное совпадение умеет только два режима: «весь пул» или «никто».

R4 это исчерпало на тех же raw S2, без новых LLM:

| шаг | кандидаты | эффект |
|---|---|---|
| 5 полей, порог 2 | 320–380 | T ≈ B1, unique_served=7 |
| 3 поля, порог 2 | 274 | ротация ещё хуже |
| + exact problem_shape | медиана 0, 54/60 пусто, recall 0.03 | T = B1 |

При этом оракул B3 = 0.77: полезные сессии в пуле есть. Золото их нашло
по смыслу истории. Теги v1 этот смысл не кодируют.

## Что из этого не следует

- «надо больше кейсов на тех же тегах» — полный корпус при том же правиле
  делает «всех подряд» ещё шире
- «подкрутить explore / decay» — при нулевых скорах и уникальных полках
  это косметика
- «v1 чуть допилить на месте» — тогда нельзя прочитать следующий NOT FIT

## Что проверяет v2

Одна предрегистрация: `problem_shape` — категория из закрытого словаря,
`ending` — содержательный исход. S3 = exact category. Рейтинг живёт на
полке, которая *может* повториться на срезе из 60.

Jaccard по старому free-text — слабый запас (handoff #64), не основная ось.
