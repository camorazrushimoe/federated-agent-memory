предлагаемые id, что увидел бы S3 относительно золота?*

Наложение вручную: все `*_how_*` → `product_howto`, цена/промо → `pricing_promo`, и т.д.

| ось | медиана n_candidates | precision vs gold | top бакет в пуле 320 |

| 19 тикетных id | **172** | **0.17** | `product_howto` 172/320 |

Recall полезных id в обоих случаях 393/393: полезные сидят внутри широкой
корзины и тонут. Гейт «медиана — десятки» на идеальных 19 id уже красный.

Вывод: первая редакция словаря чинила не ту ось. Золото режет процедуру
внутри FAQ, не тип тикета.

## Что из этого сделали в дизайне

- `problem_shape` = процедура (~31 id), не 19 типов обращений
- S3 и `tag_key` = только этот id
- ending / constraint остаются в теге для аудита, не для поиска
- гейт D4 — числа с этого замера, не «десятки»
- `checks.py` из v1 нельзя брать как есть: ending-enum и 5-польный `tag_key`

Потолок на срезе при идеальном тегере ≈ строка `unlock`: медиана ~11,
precision ~0.80. Живой S2 будет хуже. Если после S2 бакеты снова как
у 19 категорий — NOT FIT словаря, корпус не открывать.
