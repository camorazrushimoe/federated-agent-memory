Дата: 2026-08-29. Источники: `data/gold_useful.jsonl` (v1, agent-labeled),
`data/d0_slice.jsonl`, H1 `abcd_1000_pool.jsonl` + holdout.

Это не прогон тегера. Это ответ на вопрос: *если бы S2 идеально ставил
предлагаемые id, что увидел бы S3 относительно золота?*

## Оракул: 19 тикетных категорий из первой редакции v2

Наложение вручную: все `*_how_*` → `product_howto`, цена/промо → `pricing_promo`, и т.д.

| ось | медиана n_candidates | precision vs gold | top бакет в пуле 320 |
|---|---|---|---|
| 19 тикетных id | **172** | **0.17** | `product_howto` 172/320 |
| exact `unlock` (30 id) | **11** | **0.80** (по парам; query-mean с пустым золотом **0.62**) | каждый unlock ≈ 10–11 |

Recall полезных id в обоих случаях 393/393: полезные сидят внутри широкой
корзины и тонут. Гейт «медиана — десятки» на идеальных 19 id уже красный.

Вывод: первая редакция словаря чинила не ту ось. Золото режет процедуру
внутри FAQ, не тип тикета.

## Что из этого сделали в дизайне

- `problem_shape` = процедура / FAQ-ячейка (~33 id), не 19 типов обращений
- явная карта 30 unlock → id: [`MAP.md`](./MAP.md). Без merge `jacket`×`jeans`
- S3 и `tag_key` = только этот id
- ending / constraint остаются в теге для аудита, не для поиска
- гейт D4 — числа с этого замера, не «десятки»
- `checks.py` из v1 нельзя брать как есть: ending-enum и 5-польный `tag_key`
- фикстуры S0 — логин/jwt, не ABCD: id `login_session`, `gold_tags.jsonl` сверен с текстами

Потолок на срезе при идеальном тегере ≈ строка `unlock`: медиана ~11,
precision по парам ~0.80. Живой S2 будет хуже. Если после S2 бакеты снова как
у 19 категорий — NOT FIT словаря, корпус не открывать.

## Adversarial (повторный замер на тех же файлах)

1. **Гейт «12–28 используемых id» красный на идеале.** 30 unlock в пуле 320,
   карта 1:1 → идеальный S2 даёт ≈30 живых id. Нижняя граница гейта сдвинута
   на **24–32**: коллапс в 19 типов должен краситься, идеал — нет.
2. **D4 не видит хвост корпуса.** В полном пуле 1000 уникальных unlock = 96,
   **680 / 1000** строк вне 30 ячеек среза. `other < 10%` на пуле 320 не доказывает,
   что словарь покрывает домен. Корпус 1000 после красного D4 не открывать.
3. **Пустое золото всё равно наполняет пакет.** 14/60 query с `useful=[]`
   при exact-unlock всё равно получают ≈11 кандидатов. Query-mean precision
   падает до **0.62**. Ranker на полке = тот же id не может «выбрать пустое».
   T vs B1 после зелёного D4 — это ранжирование внутри ячейки, не поиск.
4. **Словарь подогнан под срез.** Это раскрыто, не спрятано. После D3 id
   не добавлять, чтобы спасти recall на тех же 60.
5. **Золото agent-labeled** (`deepseek-v4-pro`), не human. Ось совпала с
   `unlock` на 393/393 — это свойство разметки, не доказательство, что
   целая сессия полезна человеку.
6. **Шум ABCD.** `boots_how_4` содержит чат про ткань джинсов; `jeans_how_2`
   смешивает частоту стирки и фасон. Идеальный оракул по unlock это тоже
   проглатывает. Живой S2 на таких строках будет шуметь честно.
7. **Фикстуры S0 в первой редакции v2 были размечены мимо текста**
   (login → `stain_gum` / `search_broken`). C-RT2 (d-007 должен достать
   d-001 и d-002) падал бы в ноль. Исправлено: все login-фикстуры =
   `login_session`.
